Diagnosis: the Doxa environment has google-genai 1.74.0 (its uv.lock pin);
pyproject already allows >=1.74.0 and PyPI's latest is 2.22.0. Doxa also
imports the PRIVATE module google.genai._interactions, but that import is
guarded by try/except ImportError and degrades to coarser error classification,
so an upgrade will not hard-crash on import. The DR call shape itself
(client.aio.interactions.create(agent=, input=, background=, store=)) may still
need changes, since Google describes this as a breaking schema change.
Fixing it is work in the doxa-research repository, not this one.

--- configuration lesson, applies to the pilot config ---
Registered native keys (reasoning_effort, max_tokens, max_tool_calls, ...) go
FLAT in [modes.<mode>.<provider>]. The framework validates them into a
provider_request bucket and to_legacy_config nests them under the provider
namespace itself. Writing a nested [modes.<mode>.perplexity.perplexity] table
is rejected with "Unsupported provider parameter", the same guard that rejects
`background` in the openai namespace.

--- consequence for the R38 pilot ---
docs/planning/p02/doxa-pilot.config.toml overrides only the OpenAI namespace.
As it stands the pilot's three-engine fan-out cannot succeed: Gemini fails at
submission until the SDK issue is resolved, and Perplexity runs at the builtin
reasoning_effort=high, roughly USD 1.32 for that leg alone.
