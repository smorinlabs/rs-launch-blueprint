## Proposed durable execution and publication rules

Store one immutable run manifest per item revision, with item ID, effort rationale, canonical prompt hash, effective-input hash, source commits, dependency decision revisions and values, configured engine/model/provider identities, authorization reference and cost boundary, unique output paths, attempt numbers, timestamps, and artifact hashes. Actual provider charges and timing remain “unknown” until observed. Worker paths never overlap; failed and malformed raw reports remain immutable and are not treated as accepted reports for `PROJECTS.md:80`.

Provider operation transitions:

`prepared → submission-recorded → submitted → running → succeeded | partial | failed`

An interruption after submission intent but before confirmed operation ID enters `submission-unknown`. Only reconciliation may leave that state. Persist IDs as soon as received; on restart query/resume the same operation. Polling and collection are not new attempts. Honor retry-after signals and a bounded polling interval. A timeout ends active waiting and records a recoverable state; it does not prove the provider stopped. Collect successful partial artifacts and provider coverage before deciding whether any retry is needed. Retrying unsupported failed subsets, changing provider selection, or increasing the approved cost ceiling requires an explicit amended run definition. Do not invent cancellation, idempotency, or failed-provider retry capabilities before the readiness work verifies them.

Item transitions:

`planned → dependencies-ready → researching → raw-complete → synthesis → empirical-validation → auditing → publish-ready → resolved`

Exceptional states are `blocked`, `repair-needed`, `stale`, and `stopped`; the manifest records the cause and resume transition. The existing four-value index remains a summary: only the controller writes `in-progress` during all active/blocked states and `resolved` after publication. No extra index enum is introduced implicitly. A separate durable event log records attempt-level state changes and crash recovery.

Before `publish-ready`, the controller confirms all required raw inputs are accounted for; shape and substantive acceptance checks passed; producer and reviewer identities meet policy; both audits approve the exact decision revision; empirical artifacts show commands, environment, exit status and observed behavior; all blockers and conflicts are closed; registry assumptions match; and re-verification triggers are stated. Failed audits block resolution. An owner-accepted exception needs a recorded, specific disposition and any required contract amendment. Nonempty audit files are insufficient.

The single controller publishes decision revision, parameter values, dependency revision references, and resolved status together. Because several Markdown files are involved, journal the intended publication first and complete or repair it on restart before releasing consumers. Workers cannot edit registry/index directly. Owner changes invalidate affected dependent acceptance; completed old artifacts remain useful evidence but cannot be relabeled as results for a new input revision. Re-run only the invalidated work, then redo downstream empirical checks and audits against the new decision.

Reserve synthesis and audit capacity in the scheduler. A worker is eligible only if its identity meets the following rules; a numerically free slot is not sufficient. Track ready-to-synthesize, ready-to-audit, and critical-path waiting separately. Start with verified capacities and a bounded completed-raw backlog; adjust from measured pilot throughput. No 5× speedup or unverified provider quota is assumed.

## Proposed identity and audit policy

Record **actor ID** (session/job), **model ID**, **model family**, **provider**, role, and output revision for every producer, synthesizer, and auditor. Model family is the documented underlying model lineage; if lineage is uncertain, treat it as not proven independent. Terra, Luna, and Astra are all OpenAI GPT-family choices for this policy. A Doxa combined report records each contributing provider/model plus its combiner; the wrapper name is not a family.

1. No actor that produced any raw answer may synthesize that item's decision. Neither a raw producer nor the decision synthesizer may perform either audit for that item. A fresh independent actor is required; merely switching models in the same actor is insufficient.
2. The empirical auditor must use a different model family from the decision synthesizer. The two audit actors must be distinct and use different families from each other. The judgment auditor may share the synthesizer's family, but never its actor or producer role. This states the comparator missing from the current wording; it does not pretend either auditor can be from a family absent from every raw when the research already spans those families.
3. An illustrative valid assignment is a new Claude actor for synthesis, a new OpenAI GPT actor for empirical audit, and a second new Claude actor for judgment audit. None may have produced the item's raw answers. Availability and model access are not asserted by this example. Preserve the logical filenames `audit-codex.md` and `audit-fable.md`, with actual identities inside them; do not infer identity from the filename.
4. Each auditor receives the exact candidate decision revision, raw evidence and dependency snapshot, then writes its own findings and verdict. Neither rewrites the decision under audit. For web/observability, the empirical auditor independently reruns the realistic request path and applicable export, correlation, metrics, shutdown, and failure checks required by `research/RUNBOOK.md:66`.
5. Audit artifacts identify their input decision hash and unresolved findings. A changed decision requires revision-aligned re-audit; an old “PASS” cannot approve a new decision. The controller verifies this relationship before publication.

These policies make role separation and model-family diversity inspectable. They do not claim mathematical independence of model errors. The immediate action is to adopt or revise the concrete amendments, reconcile the binding documents, and exercise recovery and publication in the bounded pilot before bulk research.
