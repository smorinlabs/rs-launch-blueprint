# Architecture Decision Records (ADRs)

An Architecture Decision Record (ADR) captures **one architecturally significant
decision** — its context, the chosen design, alternatives rejected, and
consequences — so key choices remain auditable and are not re-litigated.

## Conventions (`F354`)

- **Filename:** `NNNN-kebab-title.md` (zero-padded, sequential, starting at `0001`).
- **Status lifecycle:** `Proposed` -> `Accepted` -> (`Superseded by NNNN` | `Deprecated`).
- **One decision per file:** keep ADRs focused and link to any related design
  spec in `docs/design/` or research note in `docs/research/`.
- **Immutable once accepted:** supersede with a new ADR rather than rewriting
  accepted history.

Start new records from [template.md](template.md) and register them in
`docs/SUMMARY.md` and the index table below.
