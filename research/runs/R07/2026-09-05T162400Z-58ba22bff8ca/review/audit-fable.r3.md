- **O9 — the one-command recovery is one command only for a transient
  failure.** "`workflow_dispatch` is the one-command recovery" is exact for a
  failure that will not recur; for the credential class R21 settled, an expired
  PAT needs rotation *first*, and the dispatch second. The decision does not
  mislead on this — it assigns expiry monitoring to R21 explicitly, and its
  central point against E is precisely that a scheduled retry made with an
  expired credential "fails exactly as the push run did", so E offers no
  advantage on that axis either — but the sequence is worth stating in the
  recorded form: rotate (R21), then dispatch.

- **O10 — the 60-day exposure is understated rather than overstated.** For a file
  carrying both `push` and `schedule`, the practical bite of the inactivity rule
  is the *first push after* a 60-day quiet period: a push is repository
  activity, so the disabling can only occur across a gap, and GitHub documents
  re-enabling as a deliberate act (`gh workflow enable`, or **Enable workflow**)
  with no automatic recovery. The decision states the exposure ("a public
  template that goes quiet for 60 days or is forked is the artifact most exposed
  to that") without spelling out that mechanism. Since spelling it out would
  strengthen the case the decision already makes, the omission errs toward
  understatement and is not a defect.
