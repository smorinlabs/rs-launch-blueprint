## Findings

### F1 — criterion 1 cannot detect a missing gate in the setting it is assigned to (JF-1, JF-4)

**Failed claims.**

- Line 305: "Criteria 1, 2, 5, 6 and 10 need no pseudo-terminal and are runnable in an ordinary CI job through built-binary invocations".
- U1, line 410: criteria 1, 2, 5, 6 and 10 — "the gate refuses correctly" — are proven by "built-binary invocations in an ordinary CI job on both matrix runners: `< /dev/null` from a terminal, `--no-input`, …".
- Line 294 defines criterion 1 as "`rslbp config set k v2 < /dev/null` from a terminal … **no prompt appears on the controlling terminal**, exit `2`, the `RSLB205` envelope on stderr".

**Evidence.**

1. The decision's central finding is section 13's case B (lines 77–82). A controlling terminal is present and stdin is redirected, and `crossterm` acquires the terminal anyway. Criterion 1 is that scenario. "From a terminal" and "no prompt on the controlling terminal" presuppose a controlling terminal.
2. An ordinary CI job has no controlling terminal. That setting is case A, which the decision itself labels the "negative control" (line 79). Its result is `enable_raw_mode()` → `Err`, `raw_os_error = Some(6)`.
3. The outcome table (line 140) maps `Err(InquireError::NotTTY)` — "raw mode refused (`ENOTTY`/`ENXIO`)" — to `RSLB205` / exit `2` for the consent class, "defence in depth".
4. So in the job U1 prescribes, a build that omits the gate entirely prints the same `RSLB205` envelope, exits `2` and writes nothing, exactly as the gated build does. Criterion 1 passes in both cases. Criterion 2 (`--no-input`, no `ScriptedPrompter` assertion) has the same blind spot. Criteria 3 and 10 do not, because each carries "asserted under a `ScriptedPrompter` that panics if called". The gate's unit tests (line 305) prove the predicate's truth table, not that the call site evaluates it before any prompt type is constructed.
5. The case-B failure mode is what makes the gate a bundle member (line 82: "The gate is therefore a member of this bundle"). That is the one behaviour this acceptance set must be able to observe. U5 ("That the gated template never opens `/dev/tty`") does not fill the gap either: its "What would prove it" cell names no proving check.

**Repair.** Choose either option. Both are wording changes, and neither changes a recommendation, parameter, figure or check.

- (a) Move criterion 1 into the PTY-harness set with criteria 7, 8 and 9. The harness must give the child a controlling pseudo-terminal while stdin comes from `/dev/null`, and must assert that zero bytes are written to the PTY besides the `RSLB205` envelope on stderr. Update line 305, U1 and U5 to match: U5's proving check becomes this harness run.
- (b) Keep criteria 1 and 2 in ordinary CI, but add the same instrument criteria 3 and 10 already use: "asserted under a `ScriptedPrompter` that panics if called", or an equivalent assertion that no `Prompter` was constructed. Drop "from a terminal" from criterion 1's CI form, and keep the controlling-terminal variant as a PTY check that U5 names.
