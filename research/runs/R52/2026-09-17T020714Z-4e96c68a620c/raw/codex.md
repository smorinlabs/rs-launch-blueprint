### Landscape

This item selects the TOML decoding and encoding dependency for the Rust template, not the TOML format, file name, schema-validation layer, error classification, or file-write protocol. The fixed shared capability is TOML configuration (F224); F225 and F226 are a divergent implementation choice. ### Principles and implementation

The shared requirement is a configuration document that can be decoded, validated by R53 before use, and rendered after an intentional update. Agreement is at the **capability/standard** level: F224 fixes TOML, and the pinned Python and TypeScript sources show that both parse and serialize it, while F225/F226 explicitly leave whether that is one library open. The pinned Python implementation imports `tomllib` and `tomli_w`, parses before modifying, then serializes a data mapping; the pinned TypeScript implementation imports `parse` and `stringify` from `smol-toml`. Sources retrieved 2026-09-16: `git show b08bccfb55d05f15e46a83b52c5660b1881d19f5:src/py_launch_blueprint/core/config.py` and `git show cb1cbcb2e88b898e8c081b0abbfabc1630079c00:src/lib/config.ts`, with the recorded source mapping in [config-env-logging.md](../../../../docs/port/areas/config-env-logging.md).

What must agree is semantic TOML parsing/serialization, typed `serde` integration for R53, distinguishable parse and serialize errors for R67, and safe persistence under F243. What may vary is one versus two codec crates and formatting fidelity. The two significant architectures are (1) a serde codec (`toml`) that creates canonical output and does not promise comments/spacing, and (2) a mutable syntax document (`toml_edit`) that retains most source presentation while an edit is local. `toml-rs` documents `toml` as the serde-compatible decoder/encoder and points users needing format-preserving editing to `toml_edit`; it documents that `toml_edit` preserves comments, spaces, and relative item order, but explicitly does not preserve dotted-key order or the lack of a trailing newline. Therefore no candidate provides *full* text round-trip fidelity; `toml_edit` is the qualified preservation option, not an unconditional superior default. Sources retrieved 2026-09-16: [toml README](https://github.com/toml-rs/toml/blob/main/crates/toml/README.md) and [toml_edit README](https://github.com/toml-rs/toml/blob/main/crates/toml_edit/README.md).

For this template, the source precedent needs semantic preservation, not a user-authored-format preservation guarantee: the pinned Python writer parses into a mapping and calls `tomli_w.dumps`, so it rewrites presentation even while retaining parsed data. `toml` therefore preserves the principle with less parser/document surface and composes directly with `#[derive(Deserialize, Serialize)]` in the schema R53 will own. A minimal realistic composition is `toml::from_str::<Config>(&text)` for a read, validation by R53, then `toml::to_string_pretty(&config)` for a deliberate write; `toml::de::Error` and `toml::ser::Error` remain distinguishable inputs to R67 rather than being classified here. The maintained reference examples are the crate's decoder/encoder examples and cargo-edit's use of `toml` plus `toml_edit` where it has an actual preservation requirement. Sources retrieved 2026-09-16: [toml crate source and examples](https://github.com/toml-rs/toml/tree/main/crates/toml/examples), [toml `from_str` documentation](https://docs.rs/toml/1.1.6+spec-1.1.0/toml/de/fn.from_str.html), [toml `to_string_pretty` documentation](https://docs.rs/toml/1.1.6+spec-1.1.0/toml/ser/fn.to_string_pretty.html), and [cargo-edit manifest](https://github.com/killercup/cargo-edit/blob/master/Cargo.toml).

F243 is a separate filesystem protocol, not a TOML-crate feature. Rendering first with `toml` must feed a same-directory temporary file created with mode `0600` from creation on Unix, flushed/synced, then atomically renamed over the destination; `OpenOptionsExt::mode` and `std::fs::rename`/the platform-specific durability details belong in P03's file adapter. No companion crate is required by this item, but hand-written standard-library I/O is required regardless of selecting `toml` or `toml_edit`. This preserves the baseline's interruption and confidentiality outcomes and does not turn an implementation mechanism into a TOML dependency. Sources retrieved 2026-09-16: [F243 ledger row](../../../../docs/port/COMMONALITY.md), [baseline review F243](../../../../docs/port/BASELINE-REVIEW.md), and [OpenOptionsExt::mode documentation](https://doc.rust-lang.org/std/os/unix/fs/trait.OpenOptionsExt.html). BASELINE-REVIEW: F243 — preserve restrictive permission before exposure and atomic replacement behavior through a standard-library file adapter; do not attribute either property to the selected TOML crate — evidence: [F243 baseline review](../../../../docs/port/BASELINE-REVIEW.md), retrieved 2026-09-16.

There is no like-for-like published benchmark that measures the template's small config read plus infrequent write on both target operating systems, with identical schema, features, instrumentation, and binary profile. Performance is therefore not a selection basis. The planned acceptance measurement records wall-clock read/parse/serialize latency, bytes allocated or peak RSS, release binary size, and feature set for a representative small and a deliberately large configuration on Ubuntu and macOS; no benchmark was run in this research-only item. Sources retrieved 2026-09-16: [R52 binding prompt](../inputs/prompt.md) and [toml benchmark directory](https://github.com/toml-rs/toml/tree/main/crates/toml/benches).

### Recommendation

Use one non-optional dependency: `toml = "1.1.6"` with its default features. It supplies both `Deserialize`-based parsing and `Serialize`-based writing; it is not a formatting-preservation dependency. Use `toml_edit = "0.25.15"` only in a future, separately justified change if the template adds a user-facing partial editor whose acceptance criteria require retaining comments and local layout. Source and retrieval date: [toml 1.1.6+spec-1.1.0 manifest](https://crates.io/api/v1/crates/toml/1.1.6%2Bspec-1.1.0/download), 2026-09-16.
