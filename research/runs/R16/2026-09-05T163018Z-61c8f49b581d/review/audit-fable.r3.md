1. **`review/DECISION.md:102` misstates the shape of the only maintained reference implementation cited for the selected alternative, and thereby leaves an evidence gap unstated.** The sentence reads: "`surrealdb/surrealdb` (`.github/codeql/codeql-config.yml`: `security-extended` plus `paths-ignore` over `**/tests/**`, …) is the maintained Rust reference for Alt-C". The colon scopes the list to that file's contents, and Alt-C is defined in the alternatives table as "config file with `queries` + Rust-native `paths-ignore`", prescribed with "no inline `queries:` input on that step" and guarded by A3.

   The decision's own cited source says otherwise. `raw/opus.md` records SurrealDB as "`config-file:` **and** inline `queries: security-extended`" in its practice table, and states in the Alt-B discussion: "SurrealDB currently sets both an inline `queries:` and a `config-file:`; that is safe only because their file happens to declare no `queries` key." I confirmed this against the primary source (retrieved 2026-09-09): `https://raw.githubusercontent.com/surrealdb/surrealdb/main/.github/codeql/codeql-config.yml` contains `name`, `paths-ignore` and `query-filters` and **no `queries` key at all**; `https://raw.githubusercontent.com/surrealdb/surrealdb/main/.github/workflows/codeql.yml` sets `config-file: ./.github/codeql/codeql-config.yml` at line 68 and `queries: security-extended` at line 70, both `with:` inputs on the same `github/codeql-action/init` step. SurrealDB therefore practises the hybrid the decision's B3 rationale and A3 guard reject, not Alt-C. (Its `paths-ignore` list is longer than the six globs the decision quotes — `**/test/**`, `language-tests/**`, `tests/**`, `profiling/**`, `img/**`, `docker/**` are also present — which is a fine partial quotation and is not part of this finding.)

   Why it blocks rather than being a typo: with the correction, **no adopter surveyed in either raw puts `queries` in the config file**. SurrealDB is the hybrid; `wasmCloud/wasmCloud`, `copper-project/copper-rs` and `xelis-project/xelis-blockchain` select the suite inline; `open-telemetry/opentelemetry-rust` selects nothing. The prompt requires, for every recommendation, a cited maintained reference implementation *or* a stated evidence gap. The decision asserts the former for the exact selected shape when the record supports only the latter, and the practice caveat beside it ("0 of 20 flagship Rust repositories … ship an advanced-setup CodeQL workflow at all", which I verified is a named set disjoint from the four adopters) softens the head-count without disclosing that the shape itself is unpractised among those four.

   The recommendation is not affected and should not change. Alt-C rests on executed mechanism evidence (A1–A6: the suite delta, `paths-ignore` honoured at extraction time and at workspace depth, the config's `queries` key consumed with no suite argument, the MSRV floor, the pin) and on the override hazard quoted from `init/action.yml`, none of which depends on SurrealDB. The correction in fact **strengthens** the Alt-B argument: the one flagship Rust project that ships a config file is a single `queries` key in that file away from having its suite silently overridden by its own inline input — the exact hazard B3 is written to avoid, observed in production.

   Fix (documentary, no re-execution): correct the parenthetical to say SurrealDB's config file carries `paths-ignore` and `query-filters` and that the suite is selected inline on the init step; describe SurrealDB as the maintained Rust reference for the `paths-ignore` half and the origin of the `**/` form, which is what the record supports and what the `**/` claim at `## Empirical check` and U8 already lean on; record that no surveyed Rust adopter practises queries-in-file, so the selected shape's support is mechanism evidence rather than practice; and, if the synthesizer wishes, note that SurrealDB's hybrid is live evidence for the Alt-B hazard.
