## Decision

**Repository-owned `.rs` files carry no per-file embedded license header — neither py's full-text block nor ts's intended one-line SPDX comment — and "license header" is defined by exactly what the acceptance gate enforces: (i) the leading plain-comment block of a file (blank lines, `//` non-doc line comments and `/* */` non-doc block comments, after an optional first-line `#!` shebang, ending at the first `//!`/`///`/`/*!`/`/**` doc comment, attribute or code line) contains no license, copyright or SPDX term — case-insensitive `licen[cs]`, `copyright`, `spdx`, `(c)`, `©`, `ⓒ`, or a license name `mit`, `apache`, `bsd`, `gpl`, `lgpl`, `agpl`, `mpl`, `isc`, `zlib` bounded by non-alphanumerics; and (ii) none of the five canonical license-text forms (a)–(e) listed under essential behaviors appears anywhere in the first 40 lines, in any comment or code; both rules are applied within the first 40 lines. The license is declared once, as `license = "MIT OR Apache-2.0"` in the Cargo manifest (`[workspace.package]` with `license.workspace = true` in every member, or directly in a single-package manifest), and shipped as the root `LICENSE-APACHE` and `LICENSE-MIT` files that F206 already prescribes. Enforcement is the negative check `r46_check_headers` (`review/empirical/checker-v2.sh`: layer 1 byte-identical to `raw/codex.md:430-460`, layer 2 synthesizer-authored) run over `src`, `tests`, `examples`, `benches` and `crates` after `test -s LICENSE-MIT`, `test -s LICENSE-APACHE`, `grep -Fx 'license = "MIT OR Apache-2.0"' Cargo.toml` and `cargo metadata --no-deps`, and before `cargo fmt --all -- --check`, `cargo test --workspace --all-targets` and `cargo package --workspace --allow-dirty --no-verify`. No `reuse`, `file_header`, `addlicense`, `licet`, `REUSE.toml` or `LICENSES/` directory is added. Outside the gate, by design and stated as non-claims: a license sentence inside `//!`/`///` documentation, a comment after the first attribute or code line, anything beyond line 40, and non-`.rs` files — those are code-review rules, not gate claims.** Ranked runner-up: the REUSE two-line header (`// SPDX-FileCopyrightText: <year> <holder>` / `//` / `// SPDX-License-Identifier: MIT OR Apache-2.0`) verified by `reuse lint`; it wins only if the repository starts shipping vendored or mixed-license source, or a downstream compliance requirement demands file-level copyright attribution. If a header is ever written, the only correct expression is `MIT OR Apache-2.0`; a bare `// SPDX-License-Identifier: MIT OR Apache-2.0` line is valid SPDX short-form but is not REUSE-conformant without the copyright line.

### Principles and implementation

**Shared requirement, source and agreement level.** Every distributable artifact carries one unambiguous, machine-readable license declaration that matches the complete license texts shipped with it, and no source file carries a license marker that could contradict that declaration — where "marker" is the enforced definition above. py implements this with a root `LICENSE` plus an 18-line MIT block on 51 files (`src/py_launch_blueprint/__init__.py:1`); ts implements it with a root `LICENSE` plus the `package.json` `license` field, and D-024(7) intended a repo-wide one-line SPDX comment with no insertion automation, of which only `.github/FUNDING.yml` landed (`ts-launch-blueprint/docs/port/TS_PORT_DECISIONS.md`, per the prompt). Ledger origin `different`, verdict `DIVERGENT` (F207). The agreement level is **policy**: the three repositories must agree that the manifest declaration plus the root texts are authoritative and that the declared value is the owner-fixed `license` parameter; they need not agree on whether each file repeats it. What must agree: (1) exactly one authoritative declaration in the ecosystem's package manifest (`Cargo.toml` `license`, `package.json` `license`, the Python project metadata `license` field); (2) the complete license texts at the repository root; (3) the declared expression equals the fixed parameter `MIT OR Apache-2.0`; (4) no source file carries a license marker in its leading plain-comment block, and none carries a canonical license-text form in its first 40 lines — the enforced definition; a license statement elsewhere in a file is a review-time concern, not a gate claim. What may vary: whether a file also carries a marker, and its form. The mandate's test for a justified difference is met: Cargo is the first-party distribution authority and defines `license` as an SPDX expression with `MIT OR Apache-2.0` as its example, and the Rust API Guidelines (C-PERMISSIVE) prescribe that expression with `LICENSE-APACHE` and `LICENSE-MIT` in the repository root (https://doc.rust-lang.org/cargo/reference/manifest.html and https://rust-lang.github.io/api-guidelines/necessities.html, both retrieved 2026-09-05 by the raw and cited by every evidence check).

**Why not carry py's block or ts's one-liner into Rust.** The full-text block is a drift mechanism, not a principle: clap's workspace manifest declares `license = "MIT OR Apache-2.0"` while `clap_builder/src/lib.rs` still opens with an MIT-only four-line notice (https://raw.githubusercontent.com/clap-rs/clap/master/Cargo.toml and https://raw.githubusercontent.com/clap-rs/clap/master/clap_builder/src/lib.rs, retrieved 2026-09-05; confirmed by `raw/evidence-terra.md`; the live file was re-retrieved by the synthesizer on 2026-09-05, sha256 `bd8987448be4ace2a3501375f6850261252f3485ea1c9879e137a2245359fbf5`, and its lines 1–6 are the control `review/empirical/controls/clap-header.rs`, sha256 `620d7604…`). That is the same failure ts recorded when its conversion stalled on 12 files. The surveyed current practice — Serde, Tokio, Axum and OpenZeppelin's Rust project template — opens representative `lib.rs` files with `//!` documentation or attributes and carries the license only in package metadata and root files (`https://raw.githubusercontent.com/serde-rs/serde/master/serde/src/lib.rs`, `…/tokio-rs/tokio/master/tokio/src/lib.rs`, `…/tokio-rs/axum/main/axum/src/lib.rs`, `…/OpenZeppelin/rust-project-template/master/src/lib.rs`, retrieved 2026-09-05; existence and shape re-verified by every evidence check, maintenance verified by `raw/evidence-terra-r4.md`: HTTP 200, `archived: false`, pushed 2026-08-25, 2026-09-05, 2026-09-04 and 2026-09-05 respectively; the judgment audit added star counts — Serde 10 801, Tokio 33 078, Axum 27 029, clap 16 686, the OpenZeppelin template 2 — so the template is corroborating only). This is not evidence that the ecosystem has "converged" on a universal rule — the Rust Project itself uses REUSE path annotations for its larger compliance problem (https://github.com/rust-lang/rust/blob/main/COPYRIGHT and `…/REUSE.toml`, retrieved 2026-09-05) — but it is evidence that root-only metadata is the accepted low-boilerplate shape for a uniformly licensed library, CLI or web crate, which is this template's case.

**Architecture alternatives compared** (before any tool choice, per owner amendment A5):

- (A) *Root-only Cargo metadata* — zero source boilerplate, one legal-text source, no copyright-year maintenance, no tool; the exact shape the Rust API Guidelines prescribe and Serde/Tokio/Axum/OpenZeppelin practice. Costs: a file copied out of the repository carries no license context, and a `crates/` member's archive carries no texts unless they are placed in the member directory (S6). Selected.
- (B) *Plain one-line SPDX comment* (ts's D-024(7) intent) — portable file-local identification, valid SPDX short-form (https://spdx.dev/learn/handling-license-info/, https://spdx.github.io/spdx-spec/v2.3/SPDX-license-expressions/, retrieved 2026-09-05). Costs: N copies of a value that must equal the manifest, no copyright notice so not REUSE-conformant (https://reuse.software/spec-3.3/, retrieved 2026-09-05), and — as ts showed — an incomplete rollout without automation. Rejecting it is a deliberate departure from the pre-A5 framing: `docs/port/DIVERGENCE-ANALYSIS.md:174` called D-024(7)'s one-line SPDX intent "already the org's decided answer" (`harmonize: yes`) and `docs/port/OWNER-REVIEW.md:87` records `accept`, codesign `b`; the later owner clarification (spec §2 / A5, `OWNER-REVIEW.md:15-38`) replaced "one value for every difference" with agreement at an explicit level, the prompt states that mandate supersedes inherited-mechanism wording and frames D-024(7)'s intent as prior art to weigh, and the prompt's decision question leaves "whether" open. Not selected; if file-level marking is ever required, (C) is the correct form, not (B).
- (C) *REUSE header plus `reuse lint`* — a full compliance architecture with a maintained checker (`reuse annotate`, `reuse lint`; https://reuse.software/tutorial/, https://reuse.readthedocs.io/en/stable/man/reuse-annotate.html, retrieved 2026-09-05); the Rust Project's own choice for mixed-origin trees. Costs: a Python development tool, `LICENSES/` or `REUSE.toml` obligations, and copyright lines to maintain on a template whose users rename the holder. Ranked runner-up with the condition stated above. Its OS execution was not exercised here.
- (D) *Full-text block* (py's pattern) — standalone human context in a detached file. Costs: legal text duplicated per file, review noise, and the observed MIT-only/dual-license drift (clap). The MIT-only form fails the fixed expression outright. Excluded.
- (E) *Insertion tooling* (`file_header`, `addlicense`, `licet`) — only meaningful once (B), (C) or (D) is chosen; none was gate-audited (license, dependency MSRV, RustSec, OS matrix all unverified in the raw) and none is needed for (A).
