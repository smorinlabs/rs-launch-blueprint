## Decision

**Status — this is a proposal, not an accepted result.** This decision records research and recommends a design; it is to be validated in the implementation phase (P03) against the real template, whose CI proves or disproves the recommendation. A recommendation that does not survive implementation is revised against this recorded research rather than researched again from scratch. No owner acceptance is claimed or implied: the owner has reviewed R01 only. Nothing here is an implementation: revision 6 ships no acceptance script, checker, harness or scaffold.

**Finding.** Rust has no per-file license-header requirement, and the surveyed ecosystem has not converged on one universal rule — but it has converged on a low-boilerplate shape for uniformly licensed projects. Cargo defines the manifest `license` field as an SPDX expression and gives `MIT OR Apache-2.0` as its own example (<https://doc.rust-lang.org/cargo/reference/manifest.html>, retrieved 2026-09-05); the Rust API Guidelines (C-PERMISSIVE) prescribe exactly that expression plus `LICENSE-APACHE` and `LICENSE-MIT` in the repository root (<https://rust-lang.github.io/api-guidelines/necessities.html>, retrieved 2026-09-05). Four well-regarded, currently maintained reference repositories — Serde, Tokio, Axum and OpenZeppelin's Rust project template — open their representative `lib.rs` with `//!` documentation or attributes and carry the license only in package metadata and root files (source files retrieved 2026-09-05; maintenance independently verified 2026-09-05 by the Terra evidence check via <https://api.github.com/repos/serde-rs/serde>, `…/tokio-rs/tokio`, `…/tokio-rs/axum`, `…/OpenZeppelin/rust-project-template`: HTTP 200, `archived: false`, pushed 2026-08-25, 2026-09-05, 2026-09-04, 2026-09-05). The counter-example in the same survey is the evidence against the per-file form rather than for it: clap's workspace manifest declares `license = "MIT OR Apache-2.0"` while `clap_builder/src/lib.rs` still opens with an MIT-only four-line notice (<https://raw.githubusercontent.com/clap-rs/clap/master/Cargo.toml> and <https://raw.githubusercontent.com/clap-rs/clap/master/clap_builder/src/lib.rs>, retrieved 2026-09-05; the file's lines 1–6 are kept as `review/empirical/controls/clap-header.rs`). That is the same failure mode ts recorded when its own SPDX conversion stalled on 12 files. The Rust Project itself uses REUSE path annotations rather than visible per-file headers, for the different problem of a mixed-origin tree (<https://github.com/rust-lang/rust/blob/main/COPYRIGHT> and `…/REUSE.toml`, retrieved 2026-09-05).

**Recommendation.** `rs-launch-blueprint`'s repository-owned `.rs` files carry **no per-file embedded license header** — neither py's full-text block nor ts's intended one-line SPDX comment. The license is declared once, as `license = "MIT OR Apache-2.0"` in the Cargo manifest, and shipped as the root `LICENSE-APACHE` and `LICENSE-MIT` pair that F206 already prescribes. No header-insertion or header-verification tool is adopted: no `reuse`, `file_header`, `addlicense`, `licet`, `REUSE.toml` or `LICENSES/` directory. P03 should add a negative check — described in prose under *The check P03 should build* below — that fails the build when a repository-owned source file acquires a license marker, because the recorded failure in both source repositories is drift, and a policy with no check is exactly what left ts's conversion half-finished. **Ranked runner-up:** the REUSE two-line header (`// SPDX-FileCopyrightText: <year> <holder>`, blank comment line, `// SPDX-License-Identifier: MIT OR Apache-2.0`) verified by `reuse lint`. It wins only if the repository starts shipping vendored or mixed-license source, or a downstream compliance requirement demands file-level copyright attribution. If a header is ever written, the only correct expression is `MIT OR Apache-2.0`; a bare `// SPDX-License-Identifier: MIT OR Apache-2.0` line is valid SPDX short-form but is not REUSE-conformant without a copyright line (<https://spdx.dev/learn/handling-license-info/> and <https://reuse.software/spec-3.3/>, retrieved 2026-09-05).

### Principles and implementation

**Shared requirement, its source and agreement level.** Every distributable artifact carries one unambiguous, machine-readable license declaration; the repository root carries the license texts that declaration names; and no source file carries a license marker that could contradict the declaration. py implements this with a root `LICENSE` plus an 18-line MIT block on 51 files (`src/py_launch_blueprint/__init__.py:1`). ts implements it with a root `LICENSE` plus the `package.json` `license` field, and D-024(7) intended a repo-wide one-line SPDX comment with no insertion automation, of which only `.github/FUNDING.yml` landed (`ts-launch-blueprint/docs/port/TS_PORT_DECISIONS.md`, per the prompt). Ledger origin `different`, verdict `DIVERGENT` (F207).

The agreement level is **policy**, not mechanism. The three repositories must agree that the manifest declaration plus the root texts are authoritative and that the declared value is the owner-fixed `license` parameter; they need not agree on whether each file repeats it.

| | |
|---|---|
| **What must agree** | (1) exactly one authoritative declaration in the ecosystem's package manifest (`Cargo.toml` `license`, `package.json` `license`, the Python project metadata `license` field), and, where the ecosystem has multi-package workspaces, every package resolves the same declared value; (2) the license texts named by the declaration are present at the repository root — their content and production mechanism are F206's; (3) the declared expression equals the fixed `license` parameter, `MIT OR Apache-2.0`; (4) no source file carries a license marker that can contradict the declaration. |
| **What may vary** | Whether a file also carries a marker, and what form that marker takes. Each ecosystem may choose the mechanism its tooling and conventions support. |

The research mandate's test for a justified per-ecosystem difference is met for Rust: Cargo is the first-party distribution authority and defines `license` as an SPDX expression, and the Rust API Guidelines prescribe that expression with the two root files (both sources above, retrieved 2026-09-05).

**Essential behaviors** the template must exhibit (P03 proves them; R46 recommends them):

1. The workspace manifest declares exactly `license = "MIT OR Apache-2.0"`, and `cargo metadata` resolves **every** workspace package to that expression — a member that silently declares something else is the failure this behavior exists to catch.
2. Root `LICENSE-APACHE` and `LICENSE-MIT` exist and are non-empty. Their content is F206's, asserted by nothing in R46.
3. No repository-owned `.rs` file carries a license, copyright or SPDX term in its leading plain-comment block.
4. No repository-owned `.rs` file contains one of the five canonical license-text forms in its first 40 lines.
5. The check fails, loudly and before any later build step, when behavior 1, 2, 3 or 4 is violated, when the file discovery itself errors, or when a candidate file cannot be read — and passes otherwise. It must not be possible for the check to report success because it looked at nothing.
6. `//!` crate or module documentation remains the first documentation element of every file that has it.
7. The root package's `.crate` archive contains both license files. A `crates/` member's archive does not get them automatically — see the placement note below.

**Observable acceptance criteria** — what P03 can watch on the real template, none of which R46 has observed there:

- On the generated workspace with no markers, the check exits 0 and prints one `package <name> license=MIT OR Apache-2.0` line per workspace package.
- A source file carrying any of the five canonical forms, or a license, copyright or SPDX term in its leading plain-comment block, makes the check exit 1 and name the file and the line.
- A workspace member whose manifest resolves a different expression, or none, makes the check exit 1 and name that member with its manifest path and resolved value, before any header, format, test or package step runs.
- A missing or empty `LICENSE-APACHE` or `LICENSE-MIT` makes the check exit 1.
- Discovery that yields no `.rs` file, or that reports a walk error, makes the check exit 1 rather than pass.
- The root package's `.crate` archive lists both `LICENSE-APACHE` and `LICENSE-MIT`.

**The check P03 should build.** This is a description of required behavior, not an implementation. R46 ships no script; the scripts under `review/empirical/` are the record of five rejected rounds, not the recommendation.

The check has three stages.

*Stage 1 — the manifest invariant.* Read `cargo metadata --no-deps --format-version 1` once. Require a non-empty package list in which every package's resolved `license` equals `MIT OR Apache-2.0`, and name each divergent package on stderr with its manifest path and resolved value (`null` for a package with no `license` key). `--no-deps` limits the list to workspace members, which is the intended scope. Fail here, before any later stage runs. Reading that JSON needs a parser; `jq` is the obvious one and ships on both hosted images — `jq 1.7.1` on the Ubuntu 24.04 image that `ubuntu-latest` resolves to and `jq 1.8.2` on the macOS 26 arm64 image that `macos-latest` resolves to (<https://raw.githubusercontent.com/actions/runner-images/main/images/ubuntu/Ubuntu2404-Readme.md>, image 20260831.293.1; <https://raw.githubusercontent.com/actions/runner-images/main/images/macos/macos-26-arm64-Readme.md>, image 20260831.0337.3; label mapping from <https://raw.githubusercontent.com/actions/runner-images/main/README.md>; all retrieved 2026-09-09). Provisioning it on developer machines is R42's decision. A grep-based parse of the same JSON was considered and rejected as fragile against escaping and field order.

*Stage 2 — the root files.* Require that `LICENSE-APACHE` and `LICENSE-MIT` exist and are non-empty. Nothing more: their content is F206's.

*Stage 3 — the header rule.* Over every repository-owned `.rs` file, reject two things, both bounded to the first 40 lines of a file:

- **Layer 1, the five canonical license-text forms**, case-sensitive, anywhere in those lines, in a comment or in code: (a) a line containing `SPDX-License-Identifier:`; (b) the MIT boilerplate first line `Permission is hereby granted, free of charge`; (c) the Apache appendix line `Licensed under the Apache License, Version 2.0`; (d) `Apache License` followed within three lines by `Version 2.0, January 2004`; (e) `MIT License` followed within two lines by `Copyright (c)`.
- **Layer 2, the leading plain-comment block**, case-insensitive: no license, copyright or SPDX term — `licen[cs]`, `copyright`, `spdx`, `(c)`, `©`, `ⓒ` — and no license name from the bounded list `mit`, `apache`, `bsd`, `gpl`, `lgpl`, `agpl`, `mpl`, `isc`, `zlib` delimited by non-alphanumeric characters, so that `commit`, `template`, `misc` and `simple` do not match. The leading plain-comment block is the run of blank lines, `//` non-doc line comments (`////` counts as plain) and `/* */` non-doc block comments from the top of the file, after an optional first-line `#!` shebang, ending at the first `//!`, `///`, `/*!` or `/**` doc comment, attribute or code line.

Both layers are needed, and each was established by a rejection. Layer 1 alone — the Codex raw's original detector — admits any free-form license comment: `// Copyright 2026 Example Holder` followed by `// Licensed under MIT` contains none of the five forms, and clap's own live header, the drift example that motivates the whole decision, passes it. Both revision-1 audits reproduced that admission and rejected revision 1 on it. Layer 2 alone would miss a marker that appears after the leading comment block — an SPDX tag inside `//!` documentation, or either canonical title form after a doc line — which layer 1 still catches.

Layer 2 was chosen over the stricter rule "the first non-blank line must be `//!`, `#!`, an attribute or code", which would reject every leading plain comment. The term rule closes every reproduced admission at a strictly smaller false-positive cost, and its residual cost is real and should be documented for contributors rather than hidden: a legitimate comment such as `// Parses driver license plates.` is rejected, and the remedy is to reword the comment or move it below the doc comment. Anything the rule does not cover — a license sentence inside `//!` or `///` documentation, a comment after the first attribute or code line, anything beyond line 40, and non-`.rs` files — is a code-review rule, and P03's contributor documentation should say so rather than implying the gate covers it.

**Edge cases P03 must handle.** Each was surfaced by an audit of a shipped R46 script, and each is a property of the problem, not of that script. "Repository-owned `.rs` files" should be defined by Cargo's own view of the workspace — the `cargo metadata` workspace root plus the manifest directory of any member outside it — rather than by a fixed directory list, because a fixed list is what rounds 1–4 got wrong. A definition based on `git ls-files` was considered and is not recommended: it ties the gate to git state, so untracked new files, tarball exports and working copies behave differently, while Cargo's view is what `cargo package` actually ships.

| Edge case | Why it matters | Surfaced by | What would prove P03 handles it |
|---|---|---|---|

| False positive of the layer-2 term rule | `// Parses driver license plates.` is rejected. Contributors need to know | revision-2 controls (`fp-word.rs`) | The template's own generated sources pass the check unmodified, and the contributor documentation states the rule and the remedy |

**Migration implications for the implementation plan.** Assume F206's root pair `LICENSE-APACHE` and `LICENSE-MIT`, produced by the Task 18 LICENSE update (the MIT holder line is the owner's call). Put `license = "MIT OR Apache-2.0"` in `[workspace.package]` and `license.workspace = true` in every member, or `license = "MIT OR Apache-2.0"` directly in a single-package manifest. Generate no leading plain-comment block containing a license, copyright or SPDX term or a bounded license name, and none of the five canonical forms, in `src/main.rs`, `src/lib.rs`, web modules, `build.rs`, tests, examples or benches. Build the three-stage check above and wire it into the Justfile, the hook manager and CI (R42, R37, R11 own those surfaces). Keep every package under the workspace root a workspace member, or `exclude` it deliberately and treat it as outside the manifest assertion — a workspace-layout rule that belongs to R02. Add no `REUSE.toml`, `LICENSES/` directory or header tool. Document the root pair in the README's license section in the Rust API Guidelines wording, and state in contributor documentation the review-time rule for what the gate does not cover.

**Placement note for R02, R49 and Task 18** (an observation, not a challenge to F206's principle): a package under `crates/` does not package the root license files — the root package's `.crate` archive lists them and a member's does not. If the library or web crate becomes a publishable `crates/` member, copy `LICENSE-APACHE` and `LICENSE-MIT` into that member's directory, as Serde, Tokio, Axum and clap do.

**Answers to the prompt's remaining questions.**

- HIGH (syntax): the SPDX expression is `MIT OR Apache-2.0`. The one-line form `// SPDX-License-Identifier: MIT OR Apache-2.0` is valid SPDX short-form on its own; REUSE additionally requires one or more `SPDX-FileCopyrightText:` lines, so a bare identifier line is not REUSE-conformant (SPDX and REUSE sources above, retrieved 2026-09-05; independently confirmed by `raw/evidence-terra-r4.md`).
- HIGH (prevalence): no universal rule. Current well-regarded library, async, web and template repositories rely on Cargo metadata plus root files; the Rust Project uses REUSE for its mixed tree; and one prominent CLI (clap) shows the stale full-header failure. This rests on five surveyed projects plus the Rust Project — a survey, not a census.
- HIGH (principles): above.
- MEDIUM (tooling): none adopted. The recommended check is an ordinary repository script that any hook manager or CI job can call; `reuse lint` is the verifier if the runner-up is ever activated; `licet` and `file_header` are research leads only, neither gate-audited.
- LOW (`//!` placement): no conflict in either direction. A `//` comment placed before `//!` crate documentation compiles, formats and renders documentation correctly — executed in rounds 1–5 on both operating systems — so placement does not constrain the choice. The recommended check still rejects a header-bearing file, which is the policy working as intended, not a placement problem.

**Cross-repo rationale** (a follow-on project; no py or ts file changes here). py: the manifest-plus-root-text contract makes the 18-line block on 51 files redundant; removing it — or, if a marker is wanted, converting to the REUSE two-line form under one tool — removes a 51-file drift surface. ts: D-024(7)'s intent was already the manifest-plus-root contract; the 12 stale headers are the drift this decision avoids, and finishing that conversion without automation is exactly the gap the recommended check closes in Rust. Both keep their root `LICENSE` files; their values stay `MIT` unless the owner extends the dual override to them, which is outside this item.

**Fit per surface.** CLI: `src/main.rs` opens with crate documentation or `clap` attributes; a license comment adds nothing to command behavior and creates a per-file value to keep in sync when a template user renames the package.
