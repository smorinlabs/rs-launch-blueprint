## Findings

Finding requiring a change to the decision before acceptance:

**F1 — the stated policy is wider than the enforced contract, and the gap admits the drift the decision exists to prevent.** `review/DECISION.md:7` settles "Repository-owned `.rs` files carry no per-file embedded license header"; `:13` settles the F207 ledger value as "none in repository-owned `.rs` files; … a negative header check is the acceptance gate"; `:19` states the principle as "no source file contradicts that declaration" and "what must agree (4): no source file carries a marker that disagrees with the manifest". The enforcement the decision adopts is the five-form detector (`:23` behaviors (3)–(4); `raw/codex.md:428-482`), which `raw/codex.md:426-427` describes as "It does not reject other license prose", and which the decision's Engines table (disagreement 2) narrows to "the five-form policy is the acceptance contract; anything vaguer is not claimed". That narrowing is disclosed in the raw and in the Engines table but not in the Decision paragraph, the ledger value or the principle — the three sentences the implementation plan consumes first. The consequence is concrete and reproduced (Design and evidence, above): a file whose header reads `// Licensed under MIT`, and clap's actual MIT-only header, both contradict a `MIT OR Apache-2.0` declaration and both pass the gate with exit 0. The empirical check therefore does not demonstrate the principle as the decision states it, and a template maintainer reading `:13` would believe the gate prevents exactly the clap-style drift it lets through.

Either repair path is acceptable; the synthesizer should pick one and re-execute:

- (a) Tighten `:7`, `:13` and `:19` (and the "What must agree" list) to the enforced contract: the template *generates* no per-file header; the acceptance gate rejects the five canonical forms — py's full block, ts's SPDX one-liner, the REUSE two-line header and both canonical license texts — and does not claim to detect free-form license prose, which remains a code-review rule. Add the two counterexamples above as documented "passes by design" controls so the non-claim is executable evidence.
- (b) Adopt a structural definition the gate can enforce — for example, the first non-blank line of every repository-owned `.rs` file must be `//!`, `#!`, `#[`, or code, so any leading plain `//` comment block is rejected — compare its false-positive cost against (a), and add the clap header as a negative control that must fail.

Either path produces a new decision revision and hash; both audits must then rerun on it (`research/RUNBOOK.md` §4: a historical approving audit cannot approve a new revision).
