## Findings

**F1 — unresolved (blocks approval). The reference script refuses commits and `--all` runs after an ordinary `cargo package`, because its untracked-input scan includes Git-ignored paths.**

- *Mechanism.* `scripts/check-cargo-lock.sh` (sha256 `3a57e338…ebc1`, adopted byte-for-byte from the prototype apart from the rename and comments) runs `git ls-files --others -- ':(glob)**/Cargo.toml' …` without `--exclude-standard`, deliberately ("Include ignored manifests: Cargo can resolve an untracked path dependency"), and refuses if anything is listed. This check runs before Cargo in both the default mode and `--all` mode.
- *Reproduction (probe P2, 2026-09-06T05:20–05:24Z).* Copy of `review/empirical/fixture/` in a fresh Git repository (fixture `.gitignore` is `target/`), cargo 1.98.0, git 2.50.1. `cargo package -p r41-core --allow-dirty --locked` with default verification wrote `target/package/r41-core-0.1.0/Cargo.toml`, `Cargo.lock`, `Cargo.toml.orig` and `src/`; `git status --short` stayed clean (ignored), but the script's listing returned `target/package/r41-core-0.1.0/Cargo.lock` and `…/Cargo.toml`. With a manifest comment staged, `bash scripts/check-cargo-lock.sh` exited 1 with `FAIL: untracked Cargo resolution inputs exist. Stage the intended inputs or move unrelated inputs outside this workspace.` With a clean index, `bash scripts/check-cargo-lock.sh --all` also exited 1 with the same message. After `rm -rf target/package`, `--all` exited 0. `cargo package --no-verify` (no extraction) did not trigger it. `cargo publish --dry-run` performs the same packaging and verification step by Cargo's documentation and was not run here because the fixture sets `publish = false`.
- *Why the decision's disclosure does not cover it.* The decision's known-scope-limit sentence ("it treats any untracked `Cargo.toml` as a refusal, including unrelated ones") and case C3 (`stray/Cargo.toml`, a hand-placed, non-ignored file) describe user-placed files; neither anticipates Cargo's own output in the ignored build directory, and the remediation line names neither `target/` nor build output. The template ships a library and a release surface, so packaging is a routine command in the very repository this hook guards; a developer who verifies a publish locally is then unable to commit any manifest change, and a CI job that packages before `--all` fails, both with a message that does not identify the cause. The rationale for scanning ignored paths (a path dependency inside an ignored directory) does not extend to `target/`, which Cargo never uses as a dependency source.
- *What must change in the decision (bounded scope for revision 2).* Exclude `target/` from the untracked scan (for example an `:(exclude)target/` pathspec), or switch to `--exclude-standard` and state explicitly that ignored path dependencies are unsupported; add a regression case that packages a member with verification and then expects exit 0 from the default mode with a staged manifest edit and from `--all` with a clean index; rerun both legs; update the script sha256, the "only non-comment difference from `hook.sh`" statement, the known-scope-limit paragraph and the proposed regression-suite list accordingly. Neither the pattern, the command, the tier, the trigger set nor the R23 relation is affected.

The revision is small and bounded (F1's last bullet); with it, the record corrections in F2 and the wording in F4, I expect revision 2 to be approvable without further research.
