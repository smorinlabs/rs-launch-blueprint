### Landscape

This decision is in the Conventional-Commits enforcement category: Git itself supplies the `commit-msg` hook boundary, Conventional Commits is the established message-format standard, and linters are the implementation layer. The built-in/first-party bin is Git hooks plus the Conventional Commits specification; neither Rust nor Cargo provides a Conventional-Commits linter ([Git hooks](https://git-scm.com/docs/githooks), retrieved 2026-09-05; [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/), retrieved 2026-09-05). The established-standard bin is `@commitlint/cli` with `@commitlint/config-conventional`; the native-Rust up-and-comer bin is `committed`, `cocogitto`, `convco`, and `commitlint-rs` ([commitlint repository](https://github.com/conventional-changelog/commitlint), retrieved 2026-09-05; [crates.io search](https://crates.io/api/v1/crates?page=1&per_page=20&q=conventional%20commits), retrieved 2026-09-05).

The Rust Project's 2024 survey is an authoritative Rust-community source because it is published by the Rust Survey Team; it reports 7,310 completed responses and says latest stable is the most popular Rust version, supporting a stable-toolchain rather than nightly-only template choice ([2024 State of Rust survey](https://blog.rust-lang.org/2025/02/13/2024-State-Of-Rust-Survey-results/), retrieved 2026-09-05). The Conventional Commits specification is authoritative for the message grammar, and the commitlint maintainers' rules/configuration are authoritative for that tool's configurable enforcement ([specification](https://www.conventionalcommits.org/en/v1.0.0/), [commitlint configuration](https://commitlint.js.org/reference/configuration.html), [commitlint rules](https://commitlint.js.org/reference/rules.html), retrieved 2026-09-05).

Practice evidence favors commitlint rather than treating Rust-native implementation as an ecosystem requirement: the existing Python and TypeScript blueprints both use it at the hook boundary, while the maintained commitlint repository had 18,732 stars, a 2026-08-13 `v21.2.2` release, and a 2026-09-04 push ([repository endpoint](https://api.github.com/repos/conventional-changelog/commitlint), [latest release endpoint](https://api.github.com/repos/conventional-changelog/commitlint/releases/latest), retrieved 2026-09-05). The source blueprints are relevant maintained reference implementations because they are this template's direct portability evidence: Python uses an explicit Bun-local CLI path and TypeScript uses `pnpm exec` ([Python hook](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/lefthook.yml#L18-L65), [TypeScript hook](https://github.com/smorinlabs/ts-launch-blueprint/blob/cb1cbcb2e88b898e8c081b0abbfabc1630079c00/lefthook.yml#L68), retrieved 2026-09-05).

### Principles and implementation

The shared requirement is capability-level agreement, not a shared language runtime: every locally authored commit must be rejected before creation when its Conventional-Commits message violates the selected canonical type/length policy, and every pushed or pull-request commit must be checked again in CI so `--no-verify` cannot evade the policy ([R38 divergence record](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/DIVERGENCE-ANALYSIS.md#r38-commit-message-linter), retrieved 2026-09-05). The settled architectural pattern is a `commit-msg` hook; its linter executable, lockfile, config language, and CI invocation may vary by ecosystem ([ledger F148-F157](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/COMMONALITY.md#L152-L161), retrieved 2026-09-05).

The acceptance criteria are observable: the hook exits nonzero for an invalid type, a 51-character header, a non-URL 73-character body line, or a 201-character footer line; it exits zero for the canonical type list and permitted long URL body line; and CI runs the same installed binary over the PR range ([commitlint length-rule semantics](https://commitlint.js.org/reference/rules.html), retrieved 2026-09-05). The retained invariant is therefore strict tooling parity, not merely a matching YAML job name.

Architecture comparison: a native executable removes a JavaScript runtime but must faithfully parse a message file and independently configure the three field limits; a locked local commitlint installation adds Bun/Node provisioning but already supplies those rules and a shared config model ([commitlint config-conventional source](https://github.com/conventional-changelog/commitlint/blob/master/%40commitlint/config-conventional/src/index.ts), retrieved 2026-09-05). `committed` accepts `--commit-file` and supports custom types, but its `line_length`/`hard_line_length` settings are global rather than independent body and footer policies; `cocogitto` documents custom types but no field-length settings; `convco check --from-stdin` validates grammar/types but its description length applies to interactive `convco commit`; and `commitlint-rs` documents type, body, and description rules but no footer-length rule ([committed reference](https://github.com/crate-ci/committed/blob/master/docs/reference.md), [cocogitto config](https://github.com/cocogitto/cocogitto/blob/main/website/reference/config.md), [convco check implementation](https://github.com/convco/convco/blob/main/src/cmd/check.rs), [commitlint-rs rules](https://github.com/KeisukeYamashita/commitlint-rs/tree/main/web/src/content/docs/rules), retrieved 2026-09-05).

The minimal realistic implementation is a root `package.json`/`bun.lock`, `commitlint.config.mjs`, a Lefthook `commit-msg` command invoking the installed CLI by explicit path, and a CI step that installs the lockfile then invokes that same path over the checked-out PR range. This is proposed, not executed in this research run. `BASELINE-REVIEW: F149/F150/F151-F157 — portable Conventional-Commits enforcement with exact configurable policy and CI backstop — retain commitlint through a provisioned JS runtime — native candidates do not provide the independently configurable three-limit contract; evidence: https://github.com/crate-ci/committed/blob/master/docs/reference.md, https://github.com/cocogitto/cocogitto/blob/main/website/reference/config.md, https://github.com/convco/convco/blob/main/src/cmd/check.rs, https://github.com/KeisukeYamashita/commitlint-rs/tree/main/web/src/content/docs/rules (retrieved 2026-09-05).`

### Dominant choice

Use `@commitlint/cli >=21.2.2 <22` and `@commitlint/config-conventional >=21.2.2 <22`, with the lockfile pinning both to `21.2.2`; both packages are MIT and declare Node `>=22.12.0` ([CLI registry endpoint](https://registry.npmjs.org/@commitlint/cli/latest), [config registry endpoint](https://registry.npmjs.org/@commitlint/config-conventional/latest), retrieved 2026-09-05). Run the CLI through the provisioned Bun runtime as `bun ./node_modules/@commitlint/cli/cli.js --edit {1}` locally and through the same path in CI after locked installation, rather than a global executable, package script, or network-fetching runner ([Python hook failure analysis](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/lefthook.yml#L18-L65), retrieved 2026-09-05).

This selection meets the feature gate: `type-enum`, `header-max-length`, `body-max-line-length`, and `footer-max-line-length` are first-class rules, and the conventional base configuration includes the required semantic conventions ([config source](https://github.com/conventional-changelog/commitlint/blob/master/%40commitlint/config-conventional/src/index.ts), [rules reference](https://commitlint.js.org/reference/rules.html), retrieved 2026-09-05). It is not a Cargo dependency, so crate download figures, Rust MSRV, RustSec package advisories, Cargo default features, and Rust `unsafe` posture are inapplicable; the dependency-security equivalent is an npm/Bun lockfile audit, which was not run here.

### Qualified shortlist

No native crate passes every required fitness gate and the required independent field-configuration behavior, so there is no qualified Rust-native shortlist. `committed 1.1.11` is the closest native implementation but is excluded below; its 3,551 90-day downloads and 84,746 all-time downloads come from the crate endpoint, its 182 stars and 2026-02-25 release from GitHub, and it is active because the repository was pushed on 2026-09-01 ([crate endpoint](https://crates.io/api/v1/crates/committed), [versions endpoint](https://crates.io/api/v1/crates/committed/versions), [repository endpoint](https://api.github.com/repos/crate-ci/committed), [release endpoint](https://api.github.com/repos/crate-ci/committed/releases/latest), retrieved 2026-09-05).

For all native candidates, license, declared MSRV, supported-platform claims, default features/runtime coupling, binary size, compile cost, and `unsafe` posture were assessed before popularity. Their distributed binaries cover Linux and macOS where release assets show both targets; Windows assets are present where noted but Windows is not a template gate ([committed release](https://api.github.com/repos/crate-ci/committed/releases/latest), [cocogitto release](https://api.github.com/repos/cocogitto/cocogitto/releases/latest), [convco release](https://api.github.com/repos/convco/convco/releases/latest), retrieved 2026-09-05). Source-level `unsafe` and complete transitive-MS​​RV audits were not executed, so none is represented as proven unsafe-free or transitive-MS​​RV-clean.

### Excluded by gate

- `committed >=1.1.11 <2`: compatible `MIT OR Apache-2.0`, declared Rust `1.89`, and macOS/Linux/Windows release assets, but it cannot set a 72-character body limit and a distinct 200-character footer limit because its length settings apply across message lines; its native binary has normal Rust compile/install cost and no async-runtime coupling ([manifest](https://github.com/crate-ci/committed/blob/master/Cargo.toml), [reference](https://github.com/crate-ci/committed/blob/master/docs/reference.md), [release endpoint](https://api.github.com/repos/crate-ci/committed/releases/latest), retrieved 2026-09-05).
- `cocogitto >=7.0.0 <8`: MIT, declared Rust `1.78`, standalone `libgit2`-based binary, macOS/Linux/Windows assets, and custom `commit_types`, but its documented configuration lacks header/body/footer length controls and `cog check` is documented as history validation rather than a commit-message-file checker; its release build uses fat LTO, so it deliberately trades compile time for a standalone binary ([manifest](https://github.com/cocogitto/cocogitto/blob/main/Cargo.toml), [config](https://github.com/cocogitto/cocogitto/blob/main/website/reference/config.md), [check guide](https://github.com/cocogitto/cocogitto/blob/main/website/guide/check.md), [release endpoint](https://api.github.com/repos/cocogitto/cocogitto/releases/latest), retrieved 2026-09-05).
- `convco >=0.7.2 <0.8`: MIT, declared Rust `1.87`, no external runtime, Linux/macOS/Windows assets, and type checking from stdin, but `convco check` does not enforce independent header/body/footer limits; its `description.length` is for the interactive authoring command, not check-time linting ([manifest](https://github.com/convco/convco/blob/main/Cargo.toml), [check implementation](https://github.com/convco/convco/blob/main/src/cmd/check.rs), [configuration implementation](https://github.com/convco/convco/blob/main/src/conventional/config.rs), [release endpoint](https://api.github.com/repos/convco/convco/releases/latest), retrieved 2026-09-05).
- `commitlint-rs >=0.2.4 <0.3`: dual MIT/Apache-2.0 licensing, custom types, body and description-length rules, and no default crate features are documented, but no footer-length rule is documented and its workspace does not declare a `rust-version`; it therefore cannot pass the exact behavior or declared-transitive-MSRV gates ([crate endpoint](https://crates.io/api/v1/crates/commitlint-rs), [versions endpoint](https://crates.io/api/v1/crates/commitlint-rs/versions), [type rule](https://github.com/KeisukeYamashita/commitlint-rs/blob/main/web/src/content/docs/rules/type.md), [body rule](https://github.com/KeisukeYamashita/commitlint-rs/blob/main/web/src/content/docs/rules/body-max-length.md), retrieved 2026-09-05).

The prescribed RustSec package URLs for all four native candidates returned HTTP 404 on 2026-09-05, so an open-advisory count could not be independently verified; this is a fitness-gate evidence gap, not a claim of zero advisories ([committed](https://rustsec.org/packages/committed.html), [cocogitto](https://rustsec.org/packages/cocogitto.html), [convco](https://rustsec.org/packages/convco.html), [commitlint-rs](https://rustsec.org/packages/commitlint-rs.html), retrieved 2026-09-05).

### Up-and-comers

`committed` is the most credible native runner-up because it directly accepts a commit message file and an allowlisted conventional type set, but its global line-limit model cannot encode the selected 50/72/200 policy ([CLI implementation](https://github.com/crate-ci/committed/blob/master/crates/committed/src/main.rs), [reference](https://github.com/crate-ci/committed/blob/master/docs/reference.md), retrieved 2026-09-05). `cocogitto` is broader release tooling with 8,030 recent and 219,448 all-time downloads, 1,184 stars, and a 2026-03-04 release; it is stable-quiet rather than dormant because no concrete broken-build or advisory evidence was found, but its 56 open issues and more-than-six-month release age require re-verification before adoption ([crate endpoint](https://crates.io/api/v1/crates/cocogitto), [versions endpoint](https://crates.io/api/v1/crates/cocogitto/versions), [repository endpoint](https://api.github.com/repos/cocogitto/cocogitto), [open-issues endpoint](https://api.github.com/search/issues?q=repo:cocogitto/cocogitto+is:issue+is:open), retrieved 2026-09-05).

`convco` is actively released—2,159 recent and 65,575 all-time downloads, 316 stars, and `v0.7.2` published 2026-09-03—but it is a changelog/versioning tool whose check path intentionally stops short of this linter contract ([crate endpoint](https://crates.io/api/v1/crates/convco), [versions endpoint](https://crates.io/api/v1/crates/convco/versions), [repository endpoint](https://api.github.com/repos/convco/convco), [release endpoint](https://api.github.com/repos/convco/convco/releases/latest), retrieved 2026-09-05). `commitlint-rs` is active by a 2026-09-02 push but is still `0.x`, with 8,569 recent and 50,958 all-time downloads, 70 stars, and 13 open issues; it lacks the documented footer-length capability ([crate endpoint](https://crates.io/api/v1/crates/commitlint-rs), [repository endpoint](https://api.github.com/repos/KeisukeYamashita/commitlint-rs), [open-issues endpoint](https://api.github.com/search/issues?q=repo:KeisukeYamashita/commitlint-rs+is:issue+is:open), retrieved 2026-09-05).

### Fit for this template

CLI: commitlint adds no runtime dependency to the template's shipped Rust CLI because it is a development/hook/CI tool; it gives contributors one explicit, locked command that reads Git's message-file argument ([commitlint CLI](https://github.com/conventional-changelog/commitlint/tree/master/%40commitlint/cli), retrieved 2026-09-05). Library: it inspects repository metadata only and introduces no public Rust API or library dependency. Web: it has no web-runtime dependency and validates every commit regardless of whether a change touches the optional web service.

The JS runtime is an integration cost, but it is bounded to development and CI. The Python reference demonstrates why a bare shim, package script, global PATH fallback, or `bunx` fetch-on-miss is unsafe: each can select the wrong executable, silently pass an invalid commit, or fail because `node` is absent; the explicit local CLI path avoids those failure modes ([Python hook comments](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/lefthook.yml#L18-L65), retrieved 2026-09-05).

### Recommendation

Adopt commitlint through Bun, using `@commitlint/cli >=21.2.2 <22` and `@commitlint/config-conventional >=21.2.2 <22`, both lockfile-pinned at `21.2.2`; install them as root development dependencies and do not add them to any Rust crate manifest ([npm CLI metadata](https://registry.npmjs.org/@commitlint/cli/latest), [npm config metadata](https://registry.npmjs.org/@commitlint/config-conventional/latest), retrieved 2026-09-05).

Set the owned convention to `type-enum = [feat, fix, docs, style, refactor, test, chore, ci, build, perf, revert]`, `header-max-length = 50`, `body-max-line-length = 72`, and `footer-max-line-length = 200`. The explicit list is preferred over inherited defaults because F158/F160 require the generated `.gitmessage` and its consistency test to read one durable canonical value; the values preserve the TypeScript documentation/readability discipline while retaining the Python rationale for unbreakable permalink and identifier lines in footers ([TypeScript config](https://github.com/smorinlabs/ts-launch-blueprint/blob/cb1cbcb2e88b898e8c081b0abbfabc1630079c00/commitlint.config.mjs), [Python config](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/commitlint.config.mjs), retrieved 2026-09-05).

Run `bun ./node_modules/@commitlint/cli/cli.js --edit {1}` in `commit-msg`, and in CI run the same local file over the actual PR base/head range after `bun install --frozen-lockfile`; do not use a wrapper action because the same resolved package must provide both enforcement paths. Do not carry F156's author-specific relaxed configuration: an all-commit invariant must not change by PR author, and commitlint's URL exception already permits a body line containing a URL ([rule semantics](https://commitlint.js.org/reference/rules.html), retrieved 2026-09-05).

### Ranked runner-up

`committed >=1.1.11 <2` wins only if the owner changes the owned policy to a single global line-length discipline or funds a maintained adapter that proves independent header/body/footer enforcement; it is the native runner-up because it accepts `--commit-file`, exposes `allowed_types`, and ships macOS/Linux binaries ([CLI source](https://github.com/crate-ci/committed/blob/master/crates/committed/src/main.rs), [reference](https://github.com/crate-ci/committed/blob/master/docs/reference.md), [release endpoint](https://api.github.com/repos/crate-ci/committed/releases/latest), retrieved 2026-09-05). It must not be substituted while retaining the 50/72/200 parameter because that would state an acceptance policy the hook does not actually enforce.

### Tradeoffs

Commitlint gives up a Rust-only developer toolchain and adds a locked Bun/Node-compatible dependency subtree; this cost is accepted because it is dev/CI-only and buys exact per-field policy, mature shared configuration, and a direct hook/CI implementation ([npm CLI metadata](https://registry.npmjs.org/@commitlint/cli/latest), [commitlint rules](https://commitlint.js.org/reference/rules.html), retrieved 2026-09-05). Against `committed`, it gives up a standalone native executable; against `cocogitto`, it gives up integrated release tooling; against `convco`, it gives up a native stdin checker; and against `commitlint-rs`, it gives up a familiar YAML rule surface. Each runner-up fails an essential enforcement capability, so popularity, binary size, and compile-time claims cannot reverse the selection ([native-tool evidence](https://github.com/crate-ci/committed/blob/master/docs/reference.md), [cocogitto config](https://github.com/cocogitto/cocogitto/blob/main/website/reference/config.md), [convco check](https://github.com/convco/convco/blob/main/src/cmd/check.rs), [commitlint-rs rules](https://github.com/KeisukeYamashita/commitlint-rs/tree/main/web/src/content/docs/rules), retrieved 2026-09-05).

### Migration implications

Create root `package.json` and the associated Bun lockfile with the two development dependencies, `commitlint.config.mjs` with the explicit rules, `.gitmessage` derived from the owned list and limits, and a repository test that compares that template list to the config list ([commitlint config locations](https://github.com/conventional-changelog/commitlint/blob/master/README.md#config), [TypeScript consistency test](https://github.com/smorinlabs/ts-launch-blueprint/blob/cb1cbcb2e88b898e8c081b0abbfabc1630079c00/tests/repo-hygiene.test.ts#L19-L34), retrieved 2026-09-05).

Update `lefthook.yml` with the explicit `commit-msg` command and add a CI workflow/job that checks the PR range using the same local CLI path. Do not copy Python's Dependabot config split; use one config for every author. These are planned file-level changes; no template file was changed in this research run ([Python CI precedent](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/.github/workflows/commitlint.yml), retrieved 2026-09-05).

### Validation strategy

Planned hook acceptance command: `printf 'feat: valid message\n\nA body line.\n\nRefs: #1\n' | bun ./node_modules/@commitlint/cli/cli.js` exits `0`; an unknown type, a 51-character header, a non-URL 73-character body line, and a 201-character footer line each exit nonzero. A long body URL is expected to pass because commitlint documents a URL exception for `body-max-line-length` ([rules](https://commitlint.js.org/reference/rules.html), retrieved 2026-09-05).

Planned integration acceptance command: commit an invalid message through `git commit` and prove the Lefthook `commit-msg` hook rejects it; repeat with `git commit --no-verify`, then run the CI-equivalent `bun ./node_modules/@commitlint/cli/cli.js --from <base-sha> --to <head-sha>` and prove it rejects the bypassed commit. A regression test must temporarily remove `node_modules/@commitlint/cli/cli.js` and prove the hook fails rather than resolving a PATH/global command; the Python source identifies this as the relevant silent-pass oracle ([Python failure analysis](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/lefthook.yml#L18-L65), retrieved 2026-09-05).

No commands in this section were executed: the repository has no Rust template implementation yet, and this raw research task authorizes only the report.
