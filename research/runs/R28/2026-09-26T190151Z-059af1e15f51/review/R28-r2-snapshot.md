### Principles and implementation

**Shared requirement and agreement level.** Both legs identify the same principle: one dedicated linter, configured in a committed place and run identically from the Justfile, the hook and CI. Relaxations are explicit and scoped. Security-adjacent rules sit in the gate and the rest is layered. The editor shows the gate's diagnostics with as few extensions as possible (`raw/opus.md:90-94`; `raw/muse.md:78-85`). Agreement is at the **capability and policy** level. Tool names, configuration syntax and relaxation mechanisms vary by ecosystem.

| Must agree across py, ts and rs | Justified Rust difference |
|---|---|
| One linter behind three surfaces | Invocation spelling is R42's (`cargo clippy` in the recipe that owns it, `research/topics/42-dev-toolchain-provisioning/DECISION.md:519-521`) |
| Gates never mutate source (F093) | None. rs adopts ts's shape. py's `fix = true` is the `BASELINE-REVIEW` above |
| Rule selection in one committed place | Two files, one kind of setting each. Clippy refuses levels in `clippy.toml` (L8), and Cargo refuses member overrides of `[workspace.lints]` (L7), so neither file can drift into the other's job |
| Test relaxation is explicit and scoped | Clippy recognizes test context semantically (T1, T2), so path globs are unnecessary. Cargo has no per-path lint table |
| Security gap layered, not ignored | Clippy has no bandit analogue. Safe Rust plus `unsafe_code = "forbid"` removes the memory-safety classes, and CI SAST covers dataflow |
