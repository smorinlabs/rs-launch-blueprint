### Landscape

**Category and map.** R44 decides a contributor-environment pattern, not a Cargo crate: (1) built-in or first-party toolchain: native `rustup`/Cargo on each supported host; (2) established industry standard: the Dev Container Specification plus `ghcr.io/devcontainers/features/rust:1` on a Debian/Ubuntu base; (3) up-and-comer or narrower alternative: the Docker Official Image `rust:<release>-bookworm` or a bespoke image.  The last two provide a Linux development host; they do not replace the required native `macos-latest` CI lane. The Rust project lists both `aarch64-apple-darwin` and `x86_64-apple-darwin` as Tier 1 host-tool targets, whereas a Linux container is a different host target. [Rust platform support](https://doc.rust-lang.org/rustc/platform-support.html), retrieved 2026-09-16.

[Dev Container metadata reference](https://containers.dev/implementors/json_reference/), retrieved 2026-09-16. [Rust feature README](https://github.com/devcontainers/features/blob/main/src/rust/README.md), retrieved 2026-09-16. ### Principles and implementation

The shared requirement is reproducible contributor onboarding: the Python precedent supplies a container that invokes its repository-owned bootstrap, while TypeScript has no `.devcontainer/` and no recorded reason. Its agreement level is **capability and policy**, not a common container artifact: a contributor must reach the checked development environment through the repository's supported bootstrap and CI must prove Ubuntu and macOS. The pinned Python files set an image, run `sh .devcontainer/post-create.sh`, then run `make bootstrap` and `just setup`; the pinned TypeScript tree contains no `.devcontainer/`. [Python `devcontainer.json` at `b08bccfb55d05f15e46a83b52c5660b1881d19f5`](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/.devcontainer/devcontainer.json), [Python `post-create.sh` at `b08bccfb55d05f15e46a83b52c5660b1881d19f5`](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/.devcontainer/post-create.sh), [TypeScript tree at `cb1cbcb2e88b898e8c081b0abbfabc1630079c00`](https://github.com/smorinlabs/ts-launch-blueprint/tree/cb1cbcb2e88b898e8c081b0abbfabc1630079c00), retrieved 2026-09-16.

The Rust-specific implementation preserving that capability is host-native Cargo/rustup plus the existing two-level bootstrap: `make check` establishes the base toolchain and `just setup` establishes development tasks. The bootstrap split is the recorded shared pattern for F179–F182; R42 has already chosen bare Cargo/tool commands rather than a general provisioner, so an initial container would add a fourth toolchain path rather than improve the native path. [F179–F182 source evidence](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/areas/dev-experience-repo-hygiene.md), [R42 parameter record](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/PARAMETERS.md), retrieved 2026-09-16.

Observable acceptance criteria are: on a clean Ubuntu host and a clean macOS host, the documented bootstrap reaches `make check` and `just setup`; `cargo fmt --check`, `cargo clippy`, and the template checks run with the declared `Cargo.toml` `rust-version`; and no `.devcontainer/` is required to develop CLI, library, or web surfaces. These are proposed P03/CI checks, not checks run in this research report. The Rust feature's default components include `rustfmt` and `clippy`, which confirms those are normal toolchain components rather than a reason to create a container. [Rust feature README](https://github.com/devcontainers/features/blob/main/src/rust/README.md), retrieved 2026-09-16.

Affected item: R44. ### Dominant choice

**Host-native Rust toolchain with repository-owned two-level bootstrap; ship no `.devcontainer/` in the initial Rust template.** It is the smallest design that proves both owner-fixed operating systems and makes Cargo/rustup the only Rust toolchain path. This is a pattern decision; it selects no library. [Owner-fixed `target-os-matrix`](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/PARAMETERS.md), [Rust platform support](https://doc.rust-lang.org/rustc/platform-support.html), retrieved 2026-09-16.

### Excluded by gate

**Ubuntu base + Rust Feature is excluded as the initial template default.** License is compatible because the feature repository is MIT; the crate license, dependency-tree MSRV, RustSec, unsafe-code, Cargo default-feature, async-runtime, binary-size, and Cargo compile-time gates are **inapplicable** because this is an environment pattern, not a crate. `GET https://api.github.com/repos/devcontainers/features` reported MIT, 168 open issues, and no archive on 2026-09-16; the 168 figure is from `GET https://api.github.com/search/issues?q=repo:devcontainers/features+is:issue+is:open`, retrieved 2026-09-16. Its ten most recently opened issues had no maintainer comment, so median first-maintainer-response is unavailable and unanswered count is 10; this is a support signal, not a claim that the project is dormant. The ten issues and comments were checked through `GET https://api.github.com/search/issues?q=repo:devcontainers/features+is:issue+is:open+sort:created-desc&per_page=10` and `GET https://api.github.com/repos/devcontainers/features/issues/<number>/comments`, retrieved 2026-09-16.

It also fails the required fit gate as a replacement for host validation: the feature supports Linux distributions, while the owner requires CI on both Ubuntu and macOS. [Rust feature README](https://github.com/devcontainers/features/blob/main/src/rust/README.md), [owner-fixed OS matrix](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/PARAMETERS.md), retrieved 2026-09-16. More importantly, its current installer invokes `git ls-remote` to resolve versions; the condition intended to skip that lookup for a fully specified version uses `grep -o "."`, which matches every character, and current issue 1726 documents the resulting failure when unauthenticated Git access is limited. That blocks a defensible claim that an exact feature option gives a self-contained, reproducible Rust bootstrap. [Rust feature installer](https://github.com/devcontainers/features/blob/main/src/rust/install.sh), [issue 1726](https://github.com/devcontainers/features/issues/1726), retrieved 2026-09-16.

**Docker Official Image is excluded as the initial template default.** Its Apache-2.0 repository license is compatible, but all crate-only gates are inapplicable for the same reason. `GET https://api.github.com/repos/rust-lang/docker-rust` reported 537 stars, not archived, and pushed at `2026-09-08T18:15:07Z`; `GET https://api.github.com/search/issues?q=repo:rust-lang/docker-rust+is:issue+is:open` reported 36 open issues, retrieved 2026-09-16. It is Linux-only for this use and adds no Dev Container editor/user lifecycle contract, so it cannot prove the macOS lane or reduce the need for repository bootstrap. [Docker Rust README](https://github.com/rust-lang/docker-rust/blob/master/README.md), [Rust platform support](https://doc.rust-lang.org/rustc/platform-support.html), retrieved 2026-09-16.

**Host-native pattern passes the relevant gates.** It introduces no crate, unsafe boundary, async runtime, feature set, Cargo binary-size cost, or Cargo compile-time cost; all are inapplicable. It is compatible with `MIT OR Apache-2.0`, retains the declared MSRV as a `Cargo.toml`/CI contract, and can be executed and tested natively on both owner-selected OSes. The template still must execute the planned CI matrix before this claim is accepted; no such template exists yet. [Owner-fixed parameters](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/PARAMETERS.md), retrieved 2026-09-16.

### Up-and-comers

No up-and-comer is recommended. A bespoke image could pin every apt package and Rust artifact digest, but it would create a new image release/security-maintenance surface without solving native macOS validation; it is therefore a future response to measured system-dependency pain, not an initial template pattern. Dev Container Features are the established standard, not an up-and-comer. [Dev Container metadata reference](https://containers.dev/implementors/json_reference/), [Rust platform support](https://doc.rust-lang.org/rustc/platform-support.html), retrieved 2026-09-16.

### Fit for this template

**CLI.** The CLI needs the declared Rust toolchain and repository checks; a Linux-only editor environment duplicates that toolchain while leaving macOS native verification necessary. [Owner-fixed OS matrix](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/PARAMETERS.md), retrieved 2026-09-16.

**Library.** Library consumers do not use the template's editor container; the value is therefore only contributor setup, which the repository bootstrap already owns. [F179–F182 source evidence](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/areas/dev-experience-repo-hygiene.md), retrieved 2026-09-16.

**Web service.** The optional Axum web surface is a Cargo feature, not a separately mandated local service environment. A container should not pre-forward a guessed port: `forwardPorts` exists for ports that should always be forwarded, while this template has no owner-fixed web port in R44. Add a port only when the web-service owner defines one and a concrete service command needs it. [Dev Container metadata reference](https://containers.dev/implementors/json_reference/), [R69 web-surface record](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/PARAMETERS.md), retrieved 2026-09-16.

### Recommendation

Record F200 as **OMIT for the initial Rust template**: P03 must not create `.devcontainer/devcontainer.json` or `.devcontainer/post-create.sh`. Preserve the actual cross-repository agreement—repository-owned, repeatable bootstrap—and test it in both required native CI environments. The Python container remains evidence for invoking the project bootstrap when a container is justified; it is not evidence that a Rust template needs a separate Linux development host. [Pinned Python post-create script](https://github.com/smorinlabs/py-launch-blueprint/blob/b08bccfb55d05f15e46a83b52c5660b1881d19f5/.devcontainer/post-create.sh), [Divergence analysis for R44](https://github.com/smorinlabs/rs-launch-blueprint/blob/main/docs/port/DIVERGENCE-ANALYSIS.md), retrieved 2026-09-16.

### Ranked runner-up

**Conditional opt-in Dev Container: Ubuntu base plus `ghcr.io/devcontainers/features/rust:1`.** It wins only if P03/R42 validation finds a repeated, host-specific bootstrap failure or a required non-Cargo Linux system dependency that contributors cannot reasonably install natively, and only after the feature installer can be pinned and rebuilt without its version-resolution failure. Its proposed shape is a generic supported Ubuntu base; the Rust Feature configured to the exact current stable toolchain and required `rustfmt`/`clippy` components; `remoteUser: "vscode"`; a `postCreateCommand` that runs a repository script containing exactly `make bootstrap` then `just setup`; no `remoteEnv`; no duplicate VS Code extension list; and no fixed forwarded port. This is proposed fallback design, not an implemented file. [Dev Containers Rust reference](https://github.com/devcontainers/images/blob/main/src/rust/.devcontainer/devcontainer.json), [Rust feature README](https://github.com/devcontainers/features/blob/main/src/rust/README.md), [Dev Container lifecycle reference](https://containers.dev/implementors/json_reference/), retrieved 2026-09-16.

### Tradeoffs

The dominant choice gives up a one-click Linux editor environment, filesystem/process isolation, and a potential answer for unsupported host operating systems. Those benefits do not outweigh a second toolchain path, image/feature update work, Docker availability, and the inability of a Linux container to validate the required macOS target. [Rust platform support](https://doc.rust-lang.org/rustc/platform-support.html), [Rust feature README](https://github.com/devcontainers/features/blob/main/src/rust/README.md), retrieved 2026-09-16. Against the Docker Official Image, it gives up an already-built Rust layer but avoids treating a runtime image as a full development contract. [Docker Rust README](https://github.com/rust-lang/docker-rust/blob/master/README.md), retrieved 2026-09-16.

### Validation strategy

Planned P03 checks, not executed results: on `ubuntu-latest` and `macos-latest`, run `make check`, `make bootstrap`, `just setup`, `cargo fmt --check`, `cargo clippy --all-targets --all-features`, and the template test command. The commands are intentionally proposed because this Rust template does not exist yet.
