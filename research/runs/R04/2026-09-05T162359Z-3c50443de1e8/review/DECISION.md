## Decision

**Adopt the pattern "private-module root barrel + denied reachability lints + stable-lane semver gate".** The curated public surface (F014, settled) is enforced by Rust's own module privacy: every implementation module is declared `mod name;` (private) in `src/lib.rs`, and the only route to a consumer-visible name is a `pub use` line in that one file. It is hardened by three crate-root `deny` lints (`unreachable_pub`; `private_interfaces, private_bounds`; `missing_docs`) and two `compile_fail,E0603` doctests, and drift-guarded in CI by `cargo-semver-checks` `0.50.0` (executed here on macOS and Linux) running on the stable toolchain. No dependency is added to the template. `cargo-public-api` is not adopted because it requires a nightly toolchain to be installed; it is the ranked runner-up.

### Principles and implementation

**Shared requirement, source and agreement level.** Library consumers get exactly one sanctioned import surface; anything not on it is not part of the contract. Source: py `src/py_launch_blueprint/core/__init__.py:61-85` (`__all__`, 23 names) and ts `src/lib.ts:1-3,5` ("The root export is the only stable API surface (D-012(3))"), both read at the pinned trees by the Opus raw (py `b08bccfb55d05f15e46a83b52c5660b1881d19f5`, ts `cb1cbcb2e88b898e8c081b0abbfabc1630079c00`, 2026-09-05). Two agreement levels apply. The architectural pattern (one curated surface exists) is F014 and is settled. The policy level, whether the surface is enforced or only documented, is F015 and is this item; the sources disagree there. py's own design record says "`__all__` documents, it does not enforce" (`docs/design/0005-hexagonal-architecture-and-enforcement.md:298`, HEX-34); ts hand-authors a root-only `exports` map (`package.json:24`; `TS_PORT_DECISIONS.md:88`, D-012(3)) so Node's resolver refuses every other subpath. The requirement this port carries forward is ts's level: enforcement must be mechanical and non-bypassable.

**Why the design preserves the principle.** The Rust Reference states the rule that makes the enforcement native: "If an item is public, then it can be accessed externally from some module `m` if you can access all the item's ancestor modules from `m`" ([Visibility and Privacy](https://doc.rust-lang.org/reference/visibility-and-privacy.html), retrieved 2026-09-05). A `pub` item inside a private module is therefore unnameable from another crate, and a root `pub use` is the deliberate exception that publishes one name without publishing the module path. This is stronger than ts's map, not merely equal to it: ts refuses at module-resolution time in the consumer's runtime or bundler, Rust refuses at compile time with `error[E0603]` (executed, case 03), and Rust has no `require`-style bypass. The remaining layers close the ways the curated list could rot silently: `unreachable_pub` turns a `pub` item that nobody re-exported into a build error (case 04); `private_interfaces` and `private_bounds` stop a `pub(crate)` type leaking through a public signature (case 06); `missing_docs` forces every sanctioned item to carry documentation; the doctests turn "deep imports do not compile" into a test that `cargo test` runs on every commit (case 01); and `cargo-semver-checks` fails CI on a removed or renamed public item (case 09). The language mechanisms were decided by [RFC 1422 `pub(restricted)`](https://rust-lang.github.io/rfcs/1422-pub-restricted.html) and [RFC 2145 Type privacy](https://rust-lang.github.io/rfcs/2145-type-privacy.html), and the root re-export shape is the Rust Book's own guidance, ch. 14.2 "Exporting a Convenient Public API with `pub use`" ([book](https://doc.rust-lang.org/book/ch14-02-publishing-to-crates-io.html)); all retrieved 2026-09-05.
