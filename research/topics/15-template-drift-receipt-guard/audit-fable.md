## Design and evidence

**Architecture alternatives.** Five alternatives (A rebrand-in-place with `template-press`; B `cargo-generate` placeholder generation; C GitHub template repository plus a rename script; D a press-and-build CI lane; E no check) are compared on what CI can prove before any library is chosen. B is excluded on two independent grounds, owner direction and an unverifiable MSRV gate (the `cargo-generate` 0.24.0 manifest has no `rust-version`; the empirical auditor re-fetched it and recorded `rust-version: absent`). D is kept as the ranked runner-up with concrete winning conditions (macro-assembled paths, `include!` with a computed path, stale `[workspace] members` globs) and two implementation constraints sourced to `rust-github/template` and `rust-lang/cargo#9922`. This is a genuine comparison, not a ratification of the py shape.

**Field-schema correction.** Codex's raw proposed `crate_name` and `binary_name` identity keys plus `[verify].extra_fields`; Opus's raw proposed six fields and omitted `display_name`. The decision adopts seven fields. Both corrections follow from executed evidence I read in the logs: `verify-codex-field-names-{host,linux}.log` show `error: cannot load source-config: ... [identity] unknown key(s): binary_name, crate_name`, exit 2, on both legs; `verify-six-fields-{host,linux}.log` show the README title surviving as `package_name`/`repo_name` at `L1:C2`, exit 1, when `display_name` is deleted; the rebrand plan in `rebrand-and-receipt-guard-host.log` lists `[replace] README.md — fields=['display_name_spaced']`, proving the tool rewrites the field. The empirical auditor reproduced all of these.

**Substring-rewrite rule.** The rule `substring_rewrite_fields = ["app_name"]` follows from the archived run 1 (`review/evidence/run1-before-substring-rule/`): `verify-clean-host.log` shows `tests/cli.rs [content L12:C34] app_name='rslbp'` with context `env!("CARGO_BIN_EXE_rslbp")`, exit 1; `rebrand-and-receipt-guard-host.log` shows `press rebrand` exit 0 writing a receipt with `verified = true`, the post-press `grep` finding `CARGO_BIN_EXE_rslbp`, and `cargo test --workspace` exit 101 with `environment variable CARGO_BIN_EXE_rslbp not defined at compile time`. Run 2, with the rule, shows 16 of 16 cases at their recorded exit codes on both legs (`summary-host.log` and `summary-linux.log` are byte-identical). The rule is Rust-specific for a stated reason (Cargo's first-party integration-test idiom glues `app_name` as a suffix), which is the kind of justified native adaptation §2 asks for, and the decision applies py's own "let verify earn each entry" discipline to `app_name_upper`.

**The `cargo metadata` compensating control.** The gap is established from source, not asserted: Opus read `discovery.py:64-134` (Python-only discovery; `owner` and `repo_name` alone come from the git origin) and the paired runs E and F reproduce it in this run (`verify-stale-package-name-*.log`: the stale `package_name` is caught only as `undiscoverable and absent`; `verify-wrong-owner-*.log`: `owner` is cross-checked against the origin, exit 2). The control restores the four missing cross-checks natively: `tests/press_source.rs` is a Cargo integration test (auto-discovered, runs inside `cargo test`, no new CI job), analogous to py's `tests/meta/*` suite, shelling out to `cargo metadata --no-deps --format-version 1 --offline` via the `CARGO` environment variable. Preserving P1's safety property ("config-first identity, discovery as a guard") with a native check rather than diluting it is a justified design, and the decision correctly files the upstream Cargo-discovery backend as a request rather than a dependency.
